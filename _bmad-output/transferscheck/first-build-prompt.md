Multitask. You launch work. One background worker owns one wave: investigate, implement, test, and fix. Do not split a wave across sibling agents. Do not start wave N+1 beside an unfinished wave. Inside a wave, that wave's tests are written and failing before that wave's production code. Swagger and the browser are read-only checks and may run in parallel only after that wave's code exists. Fixing what those checks find is the same worker, not a new agent and not a new wave. No extra agents for docs, refactors, or later-research items. The worker's own bmad-build-auto subagents are the skill's, launched as that skill demands: blocking, same turn, never backgrounded. They are not extra Multitask siblings. If the worker cannot do that, it HALTs blocked with condition "no subagents", and you stop the build.

Each wave is one invocation of bmad-build-auto, sequential. The worker reads D:\Repo\transferscheck.com\transferscheck.com\.agents\skills\bmad-build-auto\SKILL.md and follows it immediately. From the repo root, without changing directory, it runs this command exactly once:

Exercise the wave the way a person would. Wave N+1 does not start until wave N has passed those three checks and the defects found in that pass are fixed. This message is the human asking for the commit and the push, once per wave, and only after that. The skill commits and does not push. When it returns built and the three checks passed, push that wave only. If a check was skipped, do not push: run it, fix, commit the fix, re-run the three checks, then push. Never commit secrets, .env, user-secrets, service-account JSON, or appsettings that contain credentials. Empty typed keys the pack left unset may be committed empty. If unrelated files are dirty, stop and ask. Do not stage them. If a secret was committed, stop and ask. Do not push it. If there is no upstream, stop and ask. Do not invent a remote.
